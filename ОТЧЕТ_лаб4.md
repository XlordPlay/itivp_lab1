## 1 ЦЕЛЬ РАБОТЫ

Освоение управления локальным состоянием в React с использованием хуков useState и useEffect. Формирование навыков обработки побочных эффектов, асинхронных операций и динамического обновления интерфейса для реализации клиентской части курсового проекта.

---

## 2 КРАТКОЕ ОПИСАНИЕ ПРИЛОЖЕНИЯ

На Vite собрано одностраничное React-приложение учёта личных финансов. Пользователь ведёт список доходов и расходов: категория, сумма, описание и тип операции. Данные живут в состоянии компонента и сохраняются в localStorage, сервер в этой работе не используется.

Реализовано:

- список операций с суммой и типом (доход / расход);
- добавление, изменение и удаление через управляемую форму;
- добавление по клавише Enter (отправка формы);
- фильтр: все / только доходы / только расходы;
- статистика: сумма доходов, сумма расходов, баланс;
- загрузка из localStorage при открытии страницы, если записи уже есть, иначе три стартовых операции;
- автосохранение с задержкой 500 мс после изменения списка;
- имитация загрузки 1 секунда при старте;
- заголовок вкладки `Финансы (N)` по числу операций.

Запуск: в папке `client` выполнить `npm install` и `npm run dev`. Адрес: http://localhost:5173

## 3 ОПИСАНИЕ РЕАЛИЗАЦИИ

Код клиента лежит в `client/src`. Интерфейс — компонент `components/TransactionList.jsx`. Работа с хранилищем вынесена в хук `hooks/useLocalStorage.js`.

**Рисунок 1 – Структура файлов клиента**

*Вставить скриншот дерева `client/src`: App.jsx, components/TransactionList.jsx, hooks/useLocalStorage.js.*

Хук `useLocalStorage` хранит массив операций в `useState`. При монтировании (`useEffect` с пустым массивом зависимостей) через `setTimeout` на 1 секунду читает ключ `finance_transactions`. Если строки нет, подставляет начальные операции (зарплата, продукты, транспорт). Из эффекта возвращается очистка `clearTimeout`, чтобы таймер не сработал после размонтирования.

Второй `useEffect` зависит от `[items, ready]`. Пока идёт стартовая загрузка, он ничего не пишет, чтобы не затереть хранилище пустым массивом. После загрузки ставит таймер на 500 мс и сохраняет `JSON.stringify(items)`. Это debounce: если список меняется чаще, предыдущий таймер сбрасывается.

В `TransactionList` отдельные состояния: поля формы (`form`), id редактируемой записи (`editId`), фильтр (`filter`) и текст ошибки. Поля формы контролируемые: `value` берётся из state, `onChange` его обновляет. Добавление и правка идут через функциональное обновление `setItems((prev) => ...)`, чтобы опираться на предыдущий массив.

Ещё один эффект меняет `document.title` при изменении `items.length`.

Фильтр не пишет новый массив в state: список на экране считается при рендере (`filter === 'all'` либо сравнение `item.type`). Статистика — суммы доходов и расходов по полному массиву, не по отфильтрованному.

## 5 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

### 5.1 Для чего нужен хук useState? Как обновить состояние на основе предыдущего значения?

`useState` хранит данные между рендерами и перерисовывает компонент при изменении. Чтобы опереться на прошлое значение, в setter передают функцию: `setItems((prev) => prev.filter(...))`. React подставит актуальный массив, а не тот, что был в замыкании.

### 5.2 Что такое побочный эффект (side effect)? Примеры из проекта.

Это действие вне чистого рендера: обращение к браузеру, таймер, сеть. В проекте: чтение и запись `localStorage`, `document.title`, `setTimeout` имитации загрузки.

### 5.3 Как работает массив зависимостей в useEffect? Что будет, если он пустой?

Эффект запускается снова, когда меняется значение из массива. Пустой массив `[]` — эффект только после первого монтирования. Так загружаются данные при старте. Без массива эффект шёл бы после каждого рендера.

### 5.4 Как загрузить данные из localStorage при монтировании?

`useEffect(() => { const raw = localStorage.getItem(key); ... }, [])`. В проекте это обёрнуто в `setTimeout` на 1 секунду. Если ключа нет, берётся начальный массив из трёх операций.

### 5.5 Почему нельзя вызывать хуки внутри условий или циклов?

React запоминает хуки по порядку вызова на каждом рендере. Условие может пропустить вызов, порядок собьётся, состояние привяжется не к тому хуку. Хуки вызывают только на верхнем уровне компонента.

### 5.6 В чём разница между localStorage и sessionStorage?

Оба хранят строки в браузере. `localStorage` живёт после закрытия вкладки и общий для вкладок одного сайта. `sessionStorage` очищается при закрытии вкладки и у каждой вкладки свой.

### 5.7 Как реализовать ленивую загрузку начального состояния из localStorage?

В `useState` передают функцию, её вызовут один раз: `useState(() => JSON.parse(localStorage.getItem(key)) || [])`. В проекте загрузка сделана эффектом с задержкой, а не инициализатором, чтобы показать ожидание «с сервера».

### 5.8 Как отладить бесконечный цикл перерендеров из useEffect?

Смотрят массив зависимостей: если эффект вызывает `setState`, а в зависимостях каждый раз новый объект или сам этот state без условия, рендер зацикливается. Убирают лишние зависимости, не создают объекты прямо в массиве зависимостей, ставят условие (у нас запись в storage не идёт, пока `ready === false`).

### 5.9 Как сохранить объект или массив в localStorage и прочитать обратно?

Хранилище принимает только строки. Запись: `localStorage.setItem(key, JSON.stringify(items))`. Чтение: `JSON.parse(localStorage.getItem(key))`.

### 5.10 Что будет, если читать состояние сразу после setState?

`setState` не меняет переменную в этой же строке. Перерисовка будет позже. Сразу после вызова в текущей функции ещё старое значение.

### 5.11 Как имитировать асинхронную загрузку через setTimeout в useEffect?

В эффекте с `[]` ставят таймер, по нему вызывают `setItems` и снимают флаг загрузки. Пока флаг ложный, рисуется «Загрузка...».

### 5.12 Какую функцию очистки можно вернуть из useEffect? Пример отмены таймера.

Функцию, которую React вызовет перед следующим запуском эффекта и при размонтировании. В проекте: `return () => clearTimeout(timer)` и у таймера загрузки, и у debounce сохранения.

### 5.13 Контролируемые и неконтролируемые компоненты формы.

Контролируемый: значение в state, `value={form.amount}` и `onChange`. Так сделана форма операции. Неконтролируемый: значением владеет DOM, читают через ref. Контролируемый проще валидировать и подставлять данные при редактировании.

### 5.14 Как сделать горячую клавишу Enter для добавления?

Форма с `onSubmit`. Enter в поле ввода отправляет форму, вызывается `submit`, та же функция, что у кнопки «Добавить».

### 5.15 Как ускорить большой список?

Не рендерить тысячи DOM-узлов сразу (виртуализация, например react-window). `useMemo` — не пересчитывать фильтр без нужды. `React.memo` — не перерисовывать карточку, если её props не менялись. В этой лабе список короткий, оптимизация не нужна.

### 5.16 Как сделать debounce автосохранения?

В `useEffect` по `[items]` ставят `setTimeout` на 500 мс с `setItem`. В cleanup — `clearTimeout`. Быстрые изменения сбрасывают таймер, в storage пишется только пауза после последнего изменения.

## ПРИЛОЖЕНИЕ А (обязательное)  
Листинг components/TransactionList.jsx

```jsx
import { useEffect, useState } from 'react';
import { useLocalStorage } from '../hooks/useLocalStorage';

const EMPTY = { type: 'expense', amount: '', category: '', description: '' };

export function TransactionList() {
  const [items, setItems, ready] = useLocalStorage();
  const [form, setForm] = useState(EMPTY);
  const [editId, setEditId] = useState(null);
  const [filter, setFilter] = useState('all');
  const [error, setError] = useState('');

  useEffect(() => {
    document.title = `Финансы (${items.length})`;
  }, [items.length]);

  function submit(event) {
    event.preventDefault();
    const amount = Number(form.amount);
    if (!form.category.trim() || !amount || amount <= 0) {
      setError('Укажите категорию и сумму больше 0');
      return;
    }
    const next = { ...form, amount, category: form.category.trim() };
    if (editId) {
      setItems((prev) => prev.map((item) => (item.id === editId ? { ...item, ...next } : item)));
    } else {
      setItems((prev) => [...prev, { ...next, id: Date.now() }]);
    }
    setForm(EMPTY);
    setEditId(null);
    setError('');
  }

  const visible = items.filter((item) => filter === 'all' || item.type === filter);
  // далее форма, кнопки фильтра и список visible
}
```

## ПРИЛОЖЕНИЕ Б (обязательное)  
Листинг hooks/useLocalStorage.js

```jsx
import { useEffect, useState } from 'react';

const KEY = 'finance_transactions';

export function useLocalStorage() {
  const [items, setItems] = useState([]);
  const [ready, setReady] = useState(false);

  useEffect(() => {
    const timer = setTimeout(() => {
      const raw = localStorage.getItem(KEY);
      setItems(raw ? JSON.parse(raw) : INITIAL);
      setReady(true);
    }, 1000);
    return () => clearTimeout(timer);
  }, []);

  useEffect(() => {
    if (!ready) return undefined;
    const timer = setTimeout(() => {
      localStorage.setItem(KEY, JSON.stringify(items));
    }, 500);
    return () => clearTimeout(timer);
  }, [items, ready]);

  return [items, setItems, ready];
}
```
